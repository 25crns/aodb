# AODB Website - User Guide

Open the site (local: http://127.0.0.1:5000 after `python app.py`, or your Vercel URL). The **left menu** switches pages. The dot at the bottom of the menu shows the database status (green = connected).

## Signing in and roles
Every visitor must sign in first. Your account has one of two roles; the menu only shows what your role may use.

| | Admin | User (operations staff) |
|---|---|---|
| Dashboard, Reports, Gates (view), Staff (view) | yes | yes |
| Flights | add, edit, delete | view + **Update status** only |
| Passengers | add, edit, delete | add, edit |
| Boarding | issue, board, cancel, delete | issue, board, cancel |
| Staff & assignments | add, assign, delete | view only |
| Gate status | change | view only |
| Audit log, SQL Lab, Users | yes | not available |

- **Password**: sidebar -> *Password* changes your own password (minimum 8 characters).
- **Sign out**: sidebar -> *Sign out*. You are also signed out automatically after 8 hours.
- **Admins** can create users, change roles, deactivate accounts and reset passwords on the **Users** page (they cannot demote or deactivate themselves).
- If you try something your role does not allow, you see: *"Not allowed: this action is for administrators only."*

## Dashboard
Summary cards (total, boarding, delayed, cancelled flights, passengers, gates available), a live **flight status board** and a status chart. The board reads from the database view `FlightOperationsView`.

## Flights
- **Search** by flight number, airline or destination; **filter** by status.
- **+ Add flight**: fill in number, airline, aircraft, airports (3-letter codes), departure/arrival times, optional gate. Arrival must not be before departure.
- **Edit**: change status, gate or times. Every status change is recorded automatically (see *Audit log*).
- **Delete**: removes the flight plus its boarding passes, assignments and history in one transaction.
- If you pick a gate that another flight uses at an overlapping time, a red message appears: *"Gate is already occupied during this time period"* - that is the gate-conflict trigger.

## Boarding
- Choose a flight (or "All flights") to see its passengers and a progress bar.
- **+ Issue boarding pass**: choose passenger, flight, seat (a seat can only be used once per flight).
- **Board**: marks the passenger as boarded. The *boarding time is filled in by the database*, not by the website. Refused if the flight is Cancelled/Departed/Arrived or the passenger already boarded.
- **Cancel** / **Delete** a pass.

## Passengers
Search, add, edit and delete passengers (fictional data only). Passport numbers must be unique. A passenger who holds a boarding pass cannot be deleted (foreign key protection) - delete the boarding pass first. Edits and deletes are logged in the Audit log.

## Staff
- **Assignments** table: who works which flight and in what duty. **+ Assign to flight** creates one.
- **Staff directory**: **+ Add staff**; delete only works for staff with no assignments.

## Gates
See each gate's terminal, type and number of active flights. Change a gate's status (Available / Occupied / Maintenance / Closed) from the dropdown.

## Reports
Charts and tables generated by SQL aggregate queries: flights by status, per airline, passengers per flight, boarding status, staff by department/role, gates by status, plus the `FlightStatisticsView` table.

## Audit log
Shows what the **triggers** wrote: flight status changes (old -> new) and passenger update/delete operations. The website never writes to these tables directly.

## SQL Lab (for the viva)
Pick any prepared query (WHERE, JOIN, GROUP BY, HAVING, subqueries, views, trigger tables), read the SQL, click **Run query** and see the result table. Only the prepared queries can run - it is safe.

## Troubleshooting
- *"Cannot reach the database"*: check the database settings (`.env` locally / Vercel environment variables) and that the database is running.
- Red error text inside a form is the database's own rule message - fix the input and resubmit.
